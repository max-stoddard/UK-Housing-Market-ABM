# HPA Expectation Recalibration Design

**Author:** Max Stoddard
**Date:** 2026-04-14
**Status:** Approved
**Scope:** `scripts/python/experiments/nmg/`, `scripts/python/calibration/nmg/`, `scripts/python/helpers/nmg/`, `scripts/python/helpers/common/`, `input-data-versions/`

## Problem

The model currently uses:
- `HPA_EXPECTATION_FACTOR = 0.44`
- `HPA_EXPECTATION_CONST = -0.007`

in the expectation rule:

`expected_hpa = factor * long_term_hpa + const`

The current provenance comment says these values were calibrated with BoE NMG Survey and Land Registry data for `2014/2018`, but the original fitting script is not preserved in the repository.

The task is therefore not to pretend that the exact historical script can be recovered. The task is to reconstruct the simplest defensible national method that:
- aligns with the current model equation
- uses the survey and PPD data logically
- gets as close as possible to the legacy coefficients
- can then be carried forward consistently into the later 2024 production recalibration for `v4.2`

## Goals

- Reproduce the legacy `HPA_EXPECTATION_FACTOR` and `HPA_EXPECTATION_CONST` as closely as possible with a transparent method.
- Keep the method family simple and defensible.
- Treat national calibration as the production default because the current model applies one shared expectation rule.
- Use a small constrained method search rather than hand-tuning.
- Use existing helper-code patterns from the NMG calibration stack wherever possible.
- Freeze the winning method family so the eventual 2024 production calibration does not silently switch methodology.

## Non-Goals

- Claiming byte-for-byte recovery of the lost historical calibration script.
- Building a large unconstrained search over arbitrary transformations.
- Making regional calibration the default production method.
- Updating any parameters other than `HPA_EXPECTATION_FACTOR` and `HPA_EXPECTATION_CONST` in this workstream.

## Current Model Contract

The runtime model contract is:
- `HouseholdBehaviour.getLongTermHPAExpectation()` applies the linear rule `long_term_hpa * factor + const`
- `HPA_YEARS_TO_CHECK = 2`
- the current HPA signal is generated by the model's market statistics code, not by an external regression at runtime

This implies that the calibration should estimate a linear mapping from an externally observed HPA signal to an externally observed expectation signal.

## Design Summary

The first deliverable is a reproduction experiment script, not the production calibration script.

That experiment will:
- construct national NMG expectation targets from `boe39`
- construct national PPD-derived HPA signals under a small set of plausible transforms
- fit the linear rule `y = factor * x + const`
- rank methods by legacy recovery quality, holdout behavior, and simplicity

The production calibration script will only be created after the experiment identifies the default method family.

## Why National First

National calibration is the default method family because:
- the current model applies one shared expectation rule with one shared factor and constant
- no region-specific expectation coefficients exist in the runtime configuration
- a national method is easier to explain and reproduce
- a regional fit would introduce extra geography-mapping assumptions that the model does not directly consume

Regional calibration remains a valid secondary robustness check later, but not the production default.

## Reproduction Experiment Design

### Response Variable

The response variable `y` is the national NMG house-price expectation implied by `boe39`.

Core rules:
- use `boe39`
- exclude `Don't know`
- weight by `we_factor`

The experiment will test a small set of reasonable band-to-percent mappings:
- exact band midpoints
- rounded band midpoints
- small alternative open-ended caps for the top and bottom categories

These variants are allowed because the main ambiguity in reconstructing the legacy method is how `boe39` was converted from ordinal bands into numeric expected HPA values.

### Predictor Variable

The predictor variable `x` is a national PPD-derived HPA signal.

The experiment will test three PPD signal variants:

1. `java_like_annualised`
- build monthly national mean price from PPD
- for anchor year `t`, compute:
  - `recent = last_3_month_sum(t)`
  - `old = same_3_month_sum(t - n_years)`
  - `x = (recent / old)^(1 / n_years) - 1`
- this is the closest match to the current Java logic

2. `annual_mean_annualised`
- build annual national mean price
- compute:
  - `x = (mean_t / mean_{t - n_years})^(1 / n_years) - 1`
- this is the clean fallback when monthly-code-faithful construction is impossible

3. `annual_mean_cumulative`
- build annual national mean price
- compute:
  - `x = mean_t / mean_{t - n_years} - 1`
- this is less code-faithful, but worth testing because the legacy calibration may have used a simpler transformation

### Anchor Logic

Because the available survey and PPD years do not line up perfectly, the experiment will make anchor pairing explicit.

The experiment will support a small explicit pairing rule:
- `survey_year -> ppd_anchor_year`

Initial candidate pairings are:
- `2014 -> 2012`
- `2016 -> 2018`
- `2024 -> 2024`

This is intentionally explicit so the experiment output clearly shows which compromise was required by the available files.

### Fit Rule

For each candidate method:
- compute survey expectation targets
- compute PPD HPA targets
- fit the linear relation `y = factor * x + const`

The fit itself stays simple:
- no higher-order terms
- no arbitrary nonlinear transforms beyond the candidate `x` construction
- no over-parameterised search

This keeps the experiment aligned with the runtime equation.

## Ranking And Decision Rule

Each candidate method will be ranked using three ordered criteria.

Primary criterion:
- Euclidean distance to the legacy target point:
  - `HPA_EXPECTATION_FACTOR = 0.44`
  - `HPA_EXPECTATION_CONST = -0.007`

Secondary criterion:
- holdout quality on `2016`
- specifically, how well the fitted line predicts the observed 2016 NMG expectation under the same survey mapping

Tertiary criterion:
- simplicity and interpretability
- prefer exact midpoint mappings over custom mappings when performance is similar
- prefer Java-like HPA construction over ad hoc transformations when performance is similar

The winning method is therefore:
- legacy-close
- behaviorally reasonable on holdout
- simpler than nearby alternatives

## Required Experiment Outputs

The reproduction experiment script must print or save:
- ranked methods table
- fitted `factor`
- fitted `const`
- distance to legacy target
- observed vs predicted `2016` expectation
- survey diagnostics:
  - rows read
  - rows used
  - `Don't know` count
  - weight totals
- PPD diagnostics:
  - years used
  - months used where relevant
  - HPA signal values by anchor
- short interpretation of why the winning method won

## Helper Reuse Pattern

The implementation should reuse the current NMG stack structure rather than introduce a one-off script shape.

Reuse targets:
- `scripts/python/helpers/common/io_properties.py`
- `scripts/python/helpers/common/cli.py`
- `scripts/python/helpers/common/math_stats.py`
- `scripts/python/helpers/nmg/parsing.py`
- existing experiment-script layout under `scripts/python/experiments/nmg/`

Expected new helper responsibilities:
- `boe39` band mapping and aggregation helpers
- lightweight linear-fit helper if the current generic fitting module does not cover this cleanly
- PPD annual and monthly HPA construction helpers

Entry scripts should remain thin:
- CLI
- file loading
- method enumeration
- output formatting

Shared logic should live in helpers.

## Transition To Production Calibration

After the reproduction experiment selects the default method family, the production calibration script will:
- use the exact same survey mapping
- use the exact same PPD signal construction
- use the exact same anchor-pairing logic style
- only change the approved production anchor set

This avoids a methodology switch between:
- the script that justifies the legacy recovery
- and the script that produces the eventual `2024` parameter update

## Production Decision Record Requirement

The eventual production decision record must include:
- chosen default method
- why it was chosen
- how closely it recovered legacy `0.44 / -0.007`
- how it behaved on 2016 holdout
- what pairing compromise was required by available files
- what production anchor set was finally used
- known risks and tradeoffs

## Risks And Assumptions

- The original `2014/2018` note may refer to a calibration procedure that cannot be reconstructed exactly from repository evidence.
- The largest ambiguity is likely the transformation from survey bands and PPD levels into comparable HPA quantities.
- Missing survey and PPD years force explicit pairing compromises.
- `2016` is useful as a holdout, but not as a complete replacement for missing historical anchor years.
- The production method should remain simple even if a more complex method scores slightly better, unless the improvement is clearly material.
